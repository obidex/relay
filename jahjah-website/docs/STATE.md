### CI shape (`.github/workflows/ci.yml`) and the merge gate

One job, **named `ci`**, on every PR and on `master`, Node 22: `tier3-guard` → `npm ci` → `npm run build` → page-count assert (`EXPECTED_PAGES` = 67 content pages — verify.sh excludes `/admin`, Astro reports 68; update it in the same PR that adds routes) → compiled-output checks → `npm run reference` + `git diff --exit-code docs/reference/` → gitleaks. **Since #51 the Verify step receives `PUBLIC_SANITY_PROJECT_ID` and `PUBLIC_SANITY_DATASET` as well as `SANITY_READ_TOKEN`** — its `env` now matches the Build step's, so the hidden-product guard resolves the store from the environment rather than from image URLs in `dist/` (F44, W132). Every action is pinned to a **commit SHA** with its tag in a trailing comment. **Since P2b-1 · T4 (#69) the `ci` job is skipped on Dependabot PRs** (a job-level `if:`; the job name stays `ci`). A bot PR reports *skipped* on every event after #69, `edited` included (an older bot PR keeps its earlier red run until its next event), and GitHub counts a skipped required check as passing. That is acceptable only because W114 forbids merging a bot PR, and only the executor or the owner merges. The skip takes `tier3-guard` with it. **Since P2b-1b (#75, W149) Vercel does not build a `dependabot/**` branch either.** `vercel.json`'s `git.deploymentEnabled` is false for that pattern. Every `ERROR` deployment in the project's history had been a Dependabot branch. It was measured after the merge: Dependabot rebased #70 onto `b3f2dc9` 68 s later, and the new head got no Vercel status and no deployment. Every earlier bot head had got one within seconds. It held again on a brand-new branch: #77's head, cut from `0f79dc9`, got no Vercel status and no deployment either. So a bot PR now shows `ci` *skipped* and nothing from Vercel, while chunk branches and `master` deploy as before. **And Vercel now deploys `.vercel/output/`**, the adapter's Build Output (W142): `static/` is a verbatim copy of `dist/`, there is no `functions/`, and `vercel.json`'s `/admin` rewrites are applied by Vercel on top of the adapter's `config.json`. CI still verifies `dist/`, and nothing checks `.vercel/output/` (F54). CI does not type-check (F55).

**`ci` IS A HARD MERGE GATE from 2026-09-02T16:20:50Z.** Ruleset `master-protection`, id **22124934**: pull request required, squash only, required check `ci` (strict), no deletion, no non-fast-forward, **no bypass actors** — the admin who created it cannot bypass it either (W100).
