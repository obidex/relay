- **W097** [2026-09-02] LESSON. **`grep -q` at the end of a pipeline inverts its own test under `set -o pipefail`.** `grep -q` exits on its first match, closing the pipe; the producer dies of SIGPIPE (141); `pipefail` promotes that to the pipeline's status. `jahjah-web-backup`'s first run deleted a valid 63 KB Sanity export reporting "no data.ndjson in the archive". It is invisible on small inputs — a toy reproduction with `cat` and three lines returns 0, because the producer finishes before the reader exits — so it only appears against the real artefact, which is why an automation's first run must come from its timer against real data. Use `grep -c` and compare the count, or capture the output and test the variable. The mirror image of the `grep -c` counts-lines-not-matches trap.

- **W103** [2026-09-02] LESSON. **Five things the chunk lane taught, each measured rather than argued.** (a) **`.` and `source` are refused by Claude Code as shell-code evaluation**, headless and interactive alike, and **no permission rule can allow them** — the refusal is not a permission decision. Every unattended job publishes to the relay by sourcing `jahjah-common.sh`; a session cannot, so a dispatched chunk could never have published a report, and because the lane reads the issue's **labels** to judge success, that would have marked every chunk failed. Sessions publish through `/opt/jahjah/session/publish-report.sh`, a wrapper one narrow rule can allow. (b) **`--allowedTools` is additive** to a repository's own allow list, so a per-run grant does not widen its standing permissions. (c) **`gh issue edit` is not atomic**: given a bad `--add-label` it applies the `--remove-label` anyway and then fails, leaving an issue with *no* state label — worse than a wrong one, because the lane then sees no `chunk:running` and books the chunk finished. **Every label move adds before it removes, as two calls.** This found a live silent-queue-loss bug: the combined form could strip `chunk:approved` without applying `chunk:running`, and the issue would match no label the poll searches for — out of the queue permanently with nothing anywhere saying so. (d) **A tmux server puts itself into its own systemd scope**, so a chunk started from a `oneshot` unit is never in that unit's cgroup and `KillMode=process` is unnecessary — and setting it anyway forfeits the cgroup kill, so a `TimeoutStartSec` firing mid-`git` orphans that git holding **fd 8, `/opt/jahjah/relay.lock`, shared by every publisher on the box**.
