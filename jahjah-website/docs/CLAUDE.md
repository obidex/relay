## 2. Stack rules — what the site IS and ISN'T

- **Astro, prerendered by default.** `export const prerender = false` only on routes that need a session or per-visitor data (account, price island, Admin Mode, `/api/*`), and only when the chunk plan names the route (W074). Adapter `@astrojs/vercel` (from P2). **No Vercel-only APIs** — KV, Blob, Edge Config, platform crons/sessions — the adapter must be swappable to `@astrojs/node` (W078).
- **Public pages carry no prices, no stock quantities, no tokens, no session logic.** Hidden/disabled products never enter static HTML, sitemap, listings or search; direct links 404 without a staff session (W077). Enforce at build time AND request time.
- **Two stores, one boundary (W075).** Sanity = content. Web DB = everything commercial and every identity. Never add a price, stock, customer or role field to a Sanity schema.
- **Vanilla CSS with design tokens** (`src/styles/global.css`), logical properties for RTL. No Tailwind/shadcn/any framework. **Vanilla JS** on pages; no React/Vue/Svelte for site features.
- **TypeScript for server-side code** (`src/middleware.ts`, `src/lib/**`, on-demand routes, DB/auth clients). Existing `.astro` pages, `src/utils/*.js`, `src/data/translations.js` stay JS — converting them is never a task (W086).
- **No new dependency** unless the chunk plan lists it by name.
- Sanity reads happen server-side only (build time or on-demand route). Never a client-side Sanity query, never a token in a client bundle.

## 3. The data contract (binding shapes; signatures in the reference)

- Sanity client: `apiVersion: '2024-01-01'`, `perspective: 'published'`, `useCdn: false`, token `SANITY_READ_TOKEN`. Every product/brand/category query carries `!(_id in path("drafts.**"))`. **Both guards stay** (W012). The `apiVersion` is pinned: anything comparing against live counts — `jahjah-web-backup-check` does — must query the same version or it is asking a different engine.
- **Four facts the generator does not extract, so they live here** (closes F12): the `apiVersion` above; **a missing image is `null`, never a URL to a static file** — `imageUrl()` returns null when there is no asset, and the template renders `NoImageTile` (inline SVG, no `<img>`, so no request that can 404). This replaced `/images/placeholder.jpg`, which was the documented fallback and never existed on the live site (W112, appended at this chunk's close); `ProductDetail.astro`'s variant data attributes are named from the source, not invented, so read the file before assuming one; and the category projection is `category->{slug, nameEn, nameAr}`.
- Product shape from `src/utils/sanity.js`: `specs` is an ARRAY of `{label, value}` (never an object); `variants` is always an array (empty = no variants); `brand` is Latin; `categoryName` localized; Arabic fields fall back to English per field, never crash, never empty. Each variant carries `sku` (from P2, W076), `modelNumber`, optional `color` slug from `COLOR_OPTIONS`, `images[]`, `imagesCard[]`.
- Image URLs: `imageUrlBuilder(client).image(src).width(w).dpr(2).auto('format').fit('max')` — cards 400, detail 800.
- `COLOR_OPTIONS` is duplicated verbatim in `product.ts` and `sanity.js`; change both in one commit (W038). `COLOR_MAP` exists only in `sanity.js`, derived from that list — it needs no separate edit. The reference generator diffs the two `COLOR_OPTIONS` literals field by field and says `EXTRACTOR MISS` rather than `IN SYNC` if it reads neither.
- `BRAND_ORDER` = DCEL, LAPON, JAHJAH, SUNNY, DSP — code constant, not a schema field (W042).
- `_key` in arrays is index-based (`en-0`, `ar-0`, `gallery-0`); never derived from text.
- Slug validator in `product.ts` strips `drafts.` and excludes both IDs — never simplify (W013).
- `src/data/products.js` and `products-ar.js` are intentional backups: not imported, not deleted. `scripts/migrate-*.mjs` are one-shot: never re-run.

## 5. Running a chunk

**Preflight (stop = BLOCKED report):** `cd /opt/jahjah/web` · `git fetch` · `HEAD == origin/master` · clean tree · **`git ls-files | wc -l` recorded, and recounted before every push** (W092: a `.gitignore` rule can silently drop files and `git add` says nothing) · `gh auth status` · `git ls-remote origin` · `npm ci` · `npm run build` exit 0 · env **names** present (`PUBLIC_SANITY_PROJECT_ID`, `PUBLIC_SANITY_DATASET`, `SANITY_READ_TOKEN`, plus any the plan lists) · read `docs/STATE.md` + `docs/reference/site.md` · list every assumption in the prompt that contradicts them.

**Per task:** branch `chunk/<name>-t<n>` → investigate (read first; "no work needed" is a valid result, W029) → implement → `/verify` → reviewer subagent (`.claude/agents/reviewer.md`) → fix → re-review → commit (Conventional Commits, no emojis) → push branch → `gh pr create` with plan, acceptance checks, preview URL → wait for CI **and for the Codex review** → merge with `gh pr merge --squash --delete-branch` **only if the plan pre-authorized this PR** and CI is green and the reviewer is clean → `/relay-report progress` → next task.

**Before merging any PR, wait for the Codex review on it and address every finding that meets THE BAR** (`AGENTS.md` asks Codex to label those P0/P1; that is a convention we request, not a behaviour anyone has yet observed) — fix it, or answer it in the PR; answer the nits or say why not. Codex (the ChatGPT GitHub app) is the **reviewer of record** (recorded as W113 at the close of chunk `P1-launch-blockers`) and reads `AGENTS.md` at the repo root. Read its verdict with `gh pr view <n> --json reviews` — it posts as a *review* by `chatgpt-codex-connector`, not as a comment. **Your own reviewer subagent remains the gate.** The Claude `review` workflow is now a **manual fallback** — `workflow_dispatch` with a PR number, for when Codex is down or silent — so it no longer reports on PRs at all, and its absence is not evidence of anything.

**Codex is somebody else's system, so treat its arrival as an assumption, not a property of ours** (W105): it was observed reviewing PRs #22 and #23 on 2026-09-02, and `docs/STATE.md` live flag 10 carries the dated version of this. Its own boilerplate says it fires on opening a PR, on a draft being marked ready, or on a `@codex review` comment — so **a draft PR gets nothing**. If no review has appeared within roughly ten minutes of opening a non-draft PR, do not read the silence as approval and do not wait indefinitely — dispatch the Claude fallback, or merge on your own reviewer plus green `ci` and **say in the report that Codex did not post**. Neither review is a required check, so a model outage can never block a merge; equally, silence from either is never approval.

**A Tier-3 PR needs the authorization line in its body**, or CI's `tier3-guard` fails it (W101):
`Tier-3: authorized by chunk <name>`. Adding it re-runs the guard; no empty commit needed.

**`CHUNK_ISSUE`** is exported by the dispatch lane and also written into the first line of the chunk prompt (`CHUNK ISSUE: #<n> …`) — read it from there, because a dispatched session cannot rely on being allowed to read its own environment.

**Never:** push to `master`, force-push, rebase `master`, retag, run `sanity dataset import|delete`, read or print `.env*`, put a secret in a report, touch Vercel/Sanity/Supabase dashboards or settings (owner-only), ship an Arabic string the plan did not authorize.

**Sanity writes and DB migrations** (GATE 1): the script/SQL in the plan is the approved text. Identifier-only corrections are allowed — publish the final text + diff in a relay file before applying. Any semantic change → BLOCKED. Live re-fetch before any field deletion (W049). A write applied ahead of approval stops the chunk and is reported for ratification.

**Interrupted?** The next session re-runs build and `/verify` from scratch; earlier claims are worthless (W058).

**Chunk end (last PR):** update `docs/STATE.md` (ledger row, HEAD, flags, next step), `docs/ROADMAP.md` register, `docs/DECISIONS.md` (append `W###`), run `npm run reference` and commit the diff → `/relay-report final` in the REPORT shape from `docs/STRATEGIST.md` §1. **Caps** come from the plan; on a cap hit, stop and report `interrupted`.

## 6. Rules for every task

- **Investigate before writing.** Read the file, check the reference, confirm assumptions. Measure compiled output before fixing cascade/layout bugs (W020).
- **Verify compiled output, not source.** `dist/` HTML for JSON-LD (`<script type="application/ld+json">` has no space before `>` — W047), hreflang, og:image, noindex; `dist/_astro/*.css` for rule order and specificity (W019, W033); page count.
- **Two halves of head-slot data:** frontmatter variables AND the `<Fragment slot="head">` emitting them (W046).
- **Bilingual discipline (W023, W025, W056).** Every user-facing string via `translations.js` + `t(lang, key)`, keys in both `en` and `ar`; every page has an `/ar/` mirror unless scoped EN-only; EN/AR mirrors diffed programmatically (W051). AR strings you draft are marked `AR: pending native review` in the PR and never merged as final copy unless the plan says the reviewer approved them. Company name exact: `شركة الجحجاح التجارية`; `JAHJAH` stays Latin (W022). AR `<title>` suffix uses `companyNameAr`.
- **GROQ:** no function calls across a reference traversal — fetch `_id`, filter on `_ref` (W048).
- **One thing at a time.** No unrelated fixes in a task, no pre-emptive refactors, no "cleanup".
- **Copy a production pattern verbatim** when one exists; adapt data, not structure (W050).
- **Low ceremony output.** State what changed, the hash, the verification. No preambles, no emojis.
- **Secrets:** `.env*` and the VPS env file are read by the process, never by you. Verify by variable *names*. A value seen anywhere outside its store is burned — report it as a finding, do not paste it.
- **Reports and PR bodies are public.** Nothing secret, no unpublished content, no draft copy, no price figures, no customer data, no deploy-hook URL.

## 7. Hard prohibitions

| Never | Why |
|---|---|
| `prerender = false` on a route the plan did not name; `output: 'server'` | Public pages stay static (W074) |
| A price, stock, customer or role field in Sanity | Two stores, one boundary (W075) |
| Prices or hidden products in static HTML/JSON/sitemap | Visibility at build time (W077) |
| Remove `perspective: 'published'` or the drafts GROQ guard | Drafts collide with slugs; pages vanish (W012) |
| Simplify the slug validator | Slug clears on every edit (W013) |
| Collapse the three `/admin` rewrites in `vercel.json` | iOS home-screen 404 (W014) |
| Delete `src/data/products*.js`; re-run `scripts/migrate-*.mjs` | Backups; one-shot migrations |
| Convert `specs` to an object; translate brand names | Templates use `.map()`; brands are Latin (W010) |
| Any Vercel-only API; a Vercel "ignored build step" | Portability (W078); deploy-hook interplay (W087) |
| Token in a client bundle or `PUBLIC_` var; `SANITY_WRITE_TOKEN` outside server env | W079 |
| Push to `master`; force push; merge without green CI + clean reviewer | W084, and now refused by GitHub itself (W100) |
| **Edit or delete the `master-protection` ruleset**; add a bypass actor | It is GATE 2's machine half. A red `ci` is fixed, never bypassed (W100) |

| **Merge a Dependabot PR as it stands** | Dependabot is a notifier, not an author (W114, appended at this chunk's close). Apply the update yourself in a chunk PR — with secrets present and the change reviewed like any other — then close the bot's PR with a comment naming that PR. A major version needs its own named chunk |
| Tailwind/shadcn/any CSS framework; React/Vue/Svelte on pages; TS in existing `.astro`/`utils` | W003, W004, W086 |
| Commit `.env*`; print a secret; put anything private in the relay | Relay is world-readable |

## 8. Pitfalls (universal — module traps go to `docs/DECISIONS.md`)

| Symptom | Cause → fix |
|---|---|
| Build: route conflicts with a higher-priority route | Drafts fetched → confirm both guards (W012) |
| Build: "Could not resolve '../X.astro'" | Filename case in import → match exactly; `git mv` via temp name (W016) |
| Scoped RTL rule outranks a state rule | Astro scope injection on leading attribute selectors → chain on `html[dir="rtl"]`; check `dist/_astro/*.css` (W019) |
| "Wrong" rule wins at equal specificity | Source order → shared rules first (W033) |
| `Astro.url.pathname` wrong in `404.astro` | Build-time value → client-side `is:inline` detection (W034) |
| Studio slug clears on edit | Validator reverted → restore (W013) |
| Live shows old content after publish | Static staleness / browser cache → check the newest Vercel deployment, hard-refresh (W039) |
| 0 JSON-LD blocks after adding data | Missing `<Fragment slot="head">` (W046) |
| `grep -c` undercounts | Counts lines, not matches → `grep -o | wc -l` |
| Studio "Tool not found: admin" | `basePath: '/admin'` missing in `sanity.config.ts` |
| Non-unique `_key` warnings | Text-derived keys → index-based |
