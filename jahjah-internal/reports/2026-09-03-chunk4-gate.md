## What changed, and why the first version deserved to be refused

Chunk 3's panel refused the old guard on two counts: its kill switch was a file the constrained
session could write, and **the documented apply flow wraps the migration into a temp file the hook
never saw**. Both are gone.

| | Chunk 3 | Now |
|---|---|---|
| Registration | `~/.claude/settings.json` — every session on the box | **project-local**, this repo only |
| Kill switch | a file the constrained session could `touch` | **none** — removing it means deleting the registration |
| The check | the argument **path** | the **content**: the SQL about to run is hashed against every file under `supabase/migrations/` |
| Apply command | assemble the wrapper by hand | **`node scripts/db-query.mjs --migration <file>`**, which builds the wrapper itself |
| Claim | "refuses any apply whose hash is not published" | **an accident guard, not a boundary** — said in four places |

## Three panel blockers, found and closed here

**1 · The guard never fired on the house apply flow.** `backup.md` §3 prescribed applying the file
*wrapped* — `begin;` + the file + a `schema_migrations` insert + `commit;` — so the argument was a
temp file and a path check never saw a migrations path. **I had reproduced in the helper the exact
hole `D228` records the first version having.** Now content-based:

```
=== the house wrapped-apply form (must REFUSE) ===
  exit=2  GATE-1 guard: refusing to apply /tmp/apply.sql.
```

**2 · The stdin lane skipped both halves.** The helper exempted `-`; the hook's `node` branch
searched only its own segment while the `psql` branch already fell back to the whole command.

```
=== the stdin lane, helper half ===  exit=2  GATE-1 guard: refusing to apply the SQL on stdin.
=== the stdin lane, hook half   ===  exit=2  GATE-1 guard: supabase/migrations/20260901120000_…
```

**3 · `GATE1_RELAY_CLONE` was an override of the trust anchor** while three documents said there was
none — point it at a repo you control and any hash is "published". Removed:

```
  GATE1_RELAY_CLONE occurrences in db-query.mjs: 0
  forged relay clone: exit=2  GATE-1 guard: refusing to apply supabase/migrations/2026090112…
```

## Four more panel findings, also fixed

- **The hook classified only the first line of a multi-line command.** `shlex` never emits a newline
  token, so `export PGPASSWORD=…` followed by a `psql` apply was one segment with head word
  `export`, and was allowed. Lines are split first now.
- **An internal classifier exception fell through to the FAIL-OPEN branch.** Only the tokeniser was
  wrapped; any later exception produced an empty verdict, which the wrapper turned into
  `PARSE_ERROR` → allow. An internal error now routes to the fail-**closed** coarse matcher.
- **The health page greped a comment banner**, so deleting the enforcement while leaving the comment
  reported ACTIVE. It now checks the enforcement itself, parses the hook registration structurally,
  and probes that `python3` exists at all — without an interpreter the hook allows everything.
- **The health page published which half was off**, on a world-readable page. It now says only
  `ACTIVE` or `DEGRADED`; the detail stays on the box. A run of fail-open `PARSE` decisions now
  raises its own attention item.

## The battery

Denied for an **unpublished** migration, every form: `psql -f`, `--file=`, `<` redirect, `\i`,
env-prefixed, `bash -c`, a `~` path, `cat … | psql`, `cat … | node … -`, multi-line, `supabase db
push`, `npx supabase db push`, `supabase --workdir . db push`, `migration up`, and a non-literal
`-f "$VAR"`. Allowed for a **published** one. Still allowed, unchanged: `bash scripts/replay-check.sh`,
`docker exec … psql -f /tmp/replay.sql`, `node scripts/db-query.mjs supabase/tests/*.sql`, the E2E
teardown, ordinary work.

The ledger backfill (`2026-09-02-chunk4-gate1-backfill.md`) put chunk 2's already-applied migration
on the record so the positive path could be tested without inventing a fake migration.

## Two things that remain true and are written down

- **It is an accident guard.** Nothing on this box binds a root session holding the database
  password. `CLAUDE.md` §11H, `STRATEGIST.md` GATE 1, `backup.md` §3 and `D228` all now say so, and
  `STRATEGIST.md` adds: *never write a stronger sentence than this one*.
- **Writing about it trips it.** A command that merely mentions a migrations path beside `psql` or
  `db-query.mjs` is denied — it blocked three of my own commands while writing this. That is the
  fail-closed cost working; the pause that used to exist no longer does, so the answer is a
  non-matching placeholder, not a workaround.
