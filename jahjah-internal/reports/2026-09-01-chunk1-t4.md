## 1. What shipped

`scripts/replay-check.sh` now runs as CI job **`replay`** on every PR and every push to `main`. It
builds the entire database from the repository's migrations, bootstrap and seeds in a throwaway
container, then asserts the security posture that build is supposed to leave behind.

**It passed on the current migration history unchanged.** The chunk made that a stop condition — a
red here would have been a deviation to report, not something to fix in place — so it is worth
stating explicitly that nothing had to be adjusted to make it green.

## 2. Why this is more than one more job

- **It resolves a recorded contradiction rather than restating it.** The canon already held both *"a
  green local suite that CI never runs is not a gate"* and *"nothing in the normal loop checks whether
  the system can be rebuilt from the repo"*. Both were true at the same time. The owner deferred the
  fix once, deliberately, to keep a CI change out of an unrelated migration PR — an informed
  exception, now spent.
- **It is the only lane that can catch the failure it exists for.** The SQL suites all run against the
  single shared live database, which is never the environment a from-scratch build strands.
- **It closes a second open item for free.** It is now the only place the money anchor's behavioural
  probe — added earlier in this chunk — runs automatically. Every other assertion for that property
  runs in a mode where the two states are indistinguishable, so before this job that proof was
  manual-only.

## 3. Two deliberate calls

**It runs always, not filtered to database changes** — which was the previously-recorded default. A
path filter makes the check *absent* rather than *green* on most pull requests, and absent looks
exactly like passing at a glance. It costs about a minute.

**It is not a hard gate, and neither is anything else here.** Branch protection is a paid feature that
returns 403 on this repository, so nothing on the platform blocks a merge past a red job. The new job
is added to the parked list of checks to require. *"Wired into CI" and "cannot be merged past" are
different claims, and only the first is true today.*

## 4. What went wrong on the way, and what it cost

This PR went red once — on the **schema-type gate added in the previous task**, not on anything T4
introduced, and on a PR that touched no schema at all. It was a flaky unauthenticated container pull
with no retry, made undiagnosable by a script that swallowed the underlying error.

I fixed the cause rather than re-running the check: retry with backoff, and surface the real stderr.
That corrective is a separate commit on this branch and is described in the T3 report, because the
defect belongs to T3's work even though CI surfaced it here. Both jobs then passed, and every job
passed on the merge.

**The reason this is worth recording:** the failure looked exactly like a transient to be re-run, and
re-running it would have "worked". A gate that flakes and cannot explain itself is worse than no gate,
because it trains everyone to click through red.
