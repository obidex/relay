sites use a plain `<img>` against a 60-second signed private-storage URL, with an eslint-disable
explaining why — so sharp never actually runs.

## 6. F6 — the automation code is now in version control

Committed as `9a758a3`. `infra/vps/` holds, **byte-for-byte as installed**: the shared library, all
six job scripts with their plain-language READMEs, and all twelve `jahjah-*` units. A drift check
comparing repo to box passed at commit time.

**The rule, recorded in `infra/vps/README.md` and in the registry:** `/opt/jahjah` is the **live
copy**, `infra/vps/` is the **source of record**, and changes deploy by **copying from the repo to the
box — never by editing on-box only.** An edit made only on the box is invisible and is lost on
rebuild; an edit made only in the repo changes nothing until copied. Both halves are required. The
README carries the install commands and the drift check; `docs/runbooks/automations.md` carries the
rule as a standing note and as step 1 of "Adding an automation".

**Runtime state is deliberately not committed:** `state/` (failure counters — restoring a stale
counter on deploy would be worse than none), `dispatcher/jobs/` (issue bodies and job output,
unbounded), scan caches and work dirs, logs and locks. gitleaks clean over the new directory.

## 8. Findings

**F7 — the one remaining critical is in the only image that is actually running.**
`portainer/portainer-ce:lts` carries **1 critical** (`CVE-2026-56854`, `golang.org/x/crypto` v0.54.0,
fixed in 0.55.0) plus 8 high. Unlike the other images it is a **long-running published service**.
Fix is a `docker pull` of the current `lts` tag and a container recreate — **not done, not
authorised**, and it needs care because the port binding must keep its host-IP prefix
(`docs/pitfalls/infra-vps.md`: ufw is inactive, so that prefix is the only wall).

**F8 — `supabase/postgres:17.6.1.167` carries 22 HIGH, and they are largely unavoidable.**
The version is pinned deliberately to match the live Postgres 17.6, so it cannot be bumped freely.
Mitigating: it runs only transiently under `scripts/replay-check.sh`, is destroyed on exit, and is
never network-exposed. Recommend accepting it and revisiting when the live database moves version.

**F9 — `next` 16.2.12 and 16.3.4 exist; this session stayed on 16.2.11.**
16.2.11 is the version the advisories name and the version approved. Flagging that the line has moved
on so the upgrade is a deliberate decision rather than drift.

**F10 — one backup exists, not seven.** `jahjah-backup` has run once. The seven-night rotation cannot
be observed until the schedule has run a week; nothing is wrong, but the "7 kept" claim is unproven
until then.
