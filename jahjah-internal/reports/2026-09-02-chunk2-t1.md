## 1. What shipped

Three controls, plus the writer change the CHECK makes mandatory:

| Control | Enforces |
|---|---|
| return-half partial-unique index | one return movement per return item |
| `SECURITY DEFINER`, `ENABLE ALWAYS` guard | never issue more than dispatched for an order line |
| new dispatch link + FK + partial-unique + CHECK | one issue movement per **dispatch** line |
| the dispatch routine populates the link | same migration — the CHECK makes it compulsory |

**The grain is the whole point.** The originally-proposed index keyed on the ORDER line, and that
cannot be applied: partial dispatch legitimately puts two issues on one order line. The dispatch line
is the unit of issue.

**The guard is `SECURITY DEFINER`, and that is load-bearing.** Sabotage-verified: reverted to the
draft's implicit `INVOKER`, an inventory-only actor over-issued 50 units against 14 dispatched and
was **accepted** — because that actor can read none of the three tables the guard reads, so both
sides of the comparison read zero. Live on the honest path, blind on the attack path.

## 3. What it does NOT close — measured, not asserted

**The panel found a real residual and I confirmed it by exploit rather than by argument.** The guard
compares quantities per order line and binds nothing else: not the dispatch line to the order line,
not the variant, not the location, not the issue against its own line's quantity.

**Measured on the live database: 8 dispatch lines carry 39 units of unspent budget** — from demo
seeds that deliberately record a dispatch with no movement — **and a 5-unit issue against an
unrelated variant at an unrelated location was ACCEPTED.**

**It is a narrowing, not a hole this opened.** Beforehand no quantity cap existed at all. So the
canon says *bounded*, not *closed*, and the module pitfalls file carries the measurement. Six
follow-ups are booked as a single migration, each needing a fresh gate; only the first has security
substance.

**This is the second task running where the panel caught me claiming more than a change delivers.**
The pattern is stable enough to name: blast radius gets measured because it is frightening, value
gets asserted because it is pleasant.

## 4. A canon failure that outlived its session

**Two decision entries were never merged.** The session that wrote them was blocked, pushed its
branch, and — correctly, being in a stop state — left the merge to the owner. The merge never came.
Meanwhile this migration, the module pitfalls file and two test sites all cited one of them as
settled rationale. **None of them checked the register contained it.** I had read its text in a relay
report, found it convincing, and cited the number.

Both are now recovered verbatim, in place, with a provenance note. The rule recorded: **a stop state
is exactly when canon most needs landing, because the code did not** — and before citing a decision,
grep for it, because a dangling citation tells the next reader a question was settled somewhere they
need not look.

**The first draft of that very entry asserted a citation census it had not run**, and named a source
that does not cite the decision at all. The panel caught it. The rule is written from that.

## 5. An incident, reported

While checking that a widened test-infrastructure script still parsed, I wrapped it in a transaction
and ran it. **The file carries its own transaction control**, so my wrapper was ignored and a
destructive-by-design cleanup ran for real against the shared development database.

**Impact was nil, and that is timing rather than precaution:** the script is scoped to test-fixture
rows, sentinel-guarded against the wrong database, and CI had run the same cleanup ninety minutes
earlier, so there was nothing left to remove — the ledger row count was identical before and after,
and seeded demo data is out of scope by construction. The subsequent full E2E run passed.

**The tool warned me twice and I read it as noise.** Those two warnings are the exact signature of a
wrapper that is not in control. Recorded, with the one-command check that would have prevented it —
and with the observation that what I actually wanted was a syntax check, not an execution.
