## 2. The design decision, and the measurement behind it

The obvious build was to regenerate from the live project using the token CI already holds. **Three
findings ruled it out**, and the second is decisive rather than a preference:

1. A gate must be **deterministic**. The platform's generator and the CLI's bundled introspector are
   different code paths that can format differently — so a baseline made with one and checked with
   the other reds on a difference nobody introduced.
2. **It could not work at all.** The CI runners are IPv4-only and the database host is IPv6-only.
3. Doing it from the repository needs **no secret**, and never touches the shared database.

What makes the hermetic form legitimate rather than a dodge is a measurement: **types generated from
the repo-built database are BYTE-IDENTICAL to types generated from the live project.** That is the
gate's premise, and it is worth more than the gate itself — it is the first direct evidence in this
project that the migration history reproduces the live schema exactly. `D216` records that if the two
ever diverge, this gate is answering a different question than it appears to.

## 3. `D208` is HALF closed, and the remaining half is the one it was about

`D208`'s complaint was that a green build proves nothing about a column drop. **It still doesn't.**
The database clients carry no schema generic, so the type-checker still cannot see a stale column
name. What exists now is the prerequisite: a types file that **cannot silently go stale**, so adopting
it later cannot bake in a wrong schema. Adoption was explicitly out of scope and is registered as a
dated follow-up rather than quietly counted as done.

## 4. Two defects the review found, and one CI found

**The review (compliance + test-validity) returned no blocker.** Four mediums, all fixed before merge:

- The generated file carried **no "do not hand-edit" banner**, breaking parity with the project's
  other generated artefacts. Fixed — and the banner is prepended to the same buffer BOTH modes
  compare, so it can never itself register as drift.
- The soundness check was only "non-empty". **In write mode a truncated-but-plausible file would have
  been committed silently and then matched deterministically by every later check** — green, and
  wrong. Fixed with a line floor and a spread of known table names.
- A file write was the one step not error-checked, so a failed write would still report success.
- The Tier-2 judgement was undocumented for a change that names a locked environment variable.

**Then CI found the one I had missed, the hard way.** The gate passed on its own PR and on `main`,
then **failed on the next PR, which touched nothing related.** Root cause: the generator introspects
by pulling a container from a public registry — an unauthenticated pull from a shared runner IP,
subject to rate limits — with no retry. **And the script swallowed the tool's stderr, so the failure
reported only "did not run" with no cause.**

The second defect is the worse one. **A gate whose failures cannot be diagnosed teaches people to
re-run red checks, which is the exact habit CI exists to prevent.** Fixed: three attempts with
backoff, and the underlying stderr printed on final failure. The retry is safe **only** because the
command is a pure read against a throwaway database, and the comment says so — and says not to copy
the pattern onto anything that writes.

**The lesson worth keeping:** I verified the original on a machine where the dependency was already
cached, so the cold-start path was never exercised. I reproduced it afterwards by deleting the cached
image. *Verifying on a warm machine is not verifying.*

## 5. One thing stated plainly

**No CI job in this repository is a hard merge gate.** Branch protection is a paid feature and the
API returns 403 here, so no required-status-check list exists at all — every job is enforced by
discipline, not by the platform. That is pre-existing and was already parked, but it was worth
confirming rather than assuming: a reviewer raised it, and the check took one command. The parked
list of contexts to require has been updated so it is correct on the day the plan changes.
**"CI is green" and "CI could have stopped it" are different claims.**
