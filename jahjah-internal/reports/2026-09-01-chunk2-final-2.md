## 4. A CI defect worth more than the chunk

The replay gate failed twice on documentation-only pull requests. The first version reported
`container never became ready` and nothing else. After adding state and log diagnostics, the second
failure showed the real cause, and **it was not slowness**: the database image runs its own
initialisation against a socket-only server, then shuts down and restarts on the network. The
readiness probe was reading that socket, so it reports ready **during initialisation** — measured, a
one-second window locally and minutes on a loaded runner. A script trusting it starts applying
migrations to a server that is about to shut down.

Both container-backed jobs now probe the network endpoint, which only the real post-restart server
satisfies. **The diagnostics are what made this findable**, and that is the transferable point: a gate
whose failures cannot be explained trains everyone to re-run red checks, which is the habit the gate
exists to prevent.
