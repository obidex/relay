## 1. `tier3-guard` — proven in both directions

A PR touching a Tier-3 path fails unless its body carries `Tier-3: authorized by chunk <name>`.
`ci-ok` now `needs:` it. On a push to `main` the job is **skipped**, which `ci-ok` already passes on —
confirmed on all three post-merge runs.

**The negative half** — scratch PR [#94](https://github.com/obidex/jahjah-internal/pull/94), one
comment appended to `scripts/grant-audit.sh`, body deliberately carrying no line:

```
tier3-guard: Tier-3 paths changed by this PR:
  .github/dependabot.yml
  .github/workflows/ci.yml
  scripts/grant-audit.sh
FAIL: this PR changes Tier-3 files but its body carries no authorization line.
    Tier-3: authorized by chunk <chunk name>

  tier3-guard: failure
  ci-ok: failure          <- the required check went red WITH it
```

That second line is the one that matters: the guard does not merely report, it takes the single
required check down, so the ruleset refuses the merge.

**The positive half** — the line was added to the *same* PR's body and nothing else changed. The
`edited` trigger started a new run and `tier3-guard` returned **SUCCESS**. That is exactly the
recovery path `edited` exists for, and it is now demonstrated rather than assumed. #94 was closed and
its branch deleted; it was never merged.

**PR-C itself is a third data point:** it touches `.github/**`, carried the line, and the guard passed
on it.

**The floor, anchored:** `supabase/.+` · `src/lib/permissions/.+` · `src/lib/authz.*` ·
`src/lib/supabase/.+` · `src/proxy\.ts` · `src/lib/money/.+` · `src/lib/shipments/landed-cost.*` ·
`src/lib/i18n/.+` · `\.github/.+` · `\.claude/.+` · `infra/vps/.+` · `scripts/.+` · `\.env.*`

**It is a floor, not a ceiling**, and the comment in `ci.yml` says so: the judgment half of
`CLAUDE.md` §9 — shared logic used across many screens, a route that quietly becomes privileged — is
not path-expressible, and a green guard is not a statement that a change is Tier 2. It is also
deliberately over-broad on `scripts/.+` and `infra/vps/.+`; over-flagging costs one line in a PR body,
under-flagging is a schema or permissions change merged without the gate.
